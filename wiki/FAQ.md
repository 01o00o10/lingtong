# 常见问题

## 灵童现在可以完全替换 Tomcat 吗？

不能作普遍承诺。当前版本可以运行标准 Spring Boot 2.7 示例和已覆盖的 Servlet
主要路径，但尚未通过完整 TCK。是否可替换必须按具体业务应用验收。

## 为什么不使用 Netty？

项目目标之一是掌握从缓冲区、Selector、协议状态机到 Servlet 分派的完整实现，
并围绕所有权、背压和有界执行建立统一约束。因此核心传输没有使用 Netty。

## 支持 Java 8 吗？

支持 Java 8 字节码和 Spring Boot 2.7 兼容线。由于 Java 8 和 Spring Boot 2.7 的
上游支持状况，生产使用者仍需采用有安全维护的发行版，并规划升级路线。

## 支持 Spring Boot 3 吗？

当前不支持。Spring Boot 3 使用 Jakarta 命名空间并要求更高 Java 版本，需要独立
兼容线，不能只替换 Maven 版本号。

## Maven Group 和 Java 包名为什么不同？

Maven Group 是 `io.github.01o00o10`，对应 GitHub 账号；Java 标识符不能以数字开头，
所以包名使用 `io.github.o1o00o10.lingtong`，首字符为字母 `o`。

## 支持持久化或分布式 Session 吗？

嵌入式 API 提供文件持久化与 JDBC SessionStore 装配入口。生产采用前仍需针对并发、
序列化兼容、数据库故障、清理策略和多节点一致性做专项验证。

## `cluster-peers` 是完整集群吗？

不是。当前用于对端心跳和状态观测，不包含完整服务发现、流量调度、自动故障转移
或透明 Session 复制。

## 国密支持情况如何？

国密验证和商业密码合规认证目前暂缓。JSSE 可插拔不等于已经完成国密协议互操作、
性能、安全与认证验证。

## 为什么公开仓库没有测试代码？

项目所有者选择公开生产源码与示例，把测试套件和设计文档保留为私有资料。因此外部
贡献者应把公开示例和自己的应用验收作为最低验证手段，同时注意这降低了外部可复现性。
