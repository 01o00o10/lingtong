# 安全指南

## 部署基线

- 使用仍在供应商安全支持期内的 JDK，并及时更新补丁。
- 明确设置请求头、请求体、参数、Cookie、响应和队列上限。
- 管理端绑定 `127.0.0.1` 或隔离管理网，不直接暴露公网。
- 管理令牌通过环境变量或密钥系统注入，读令牌与操作令牌分离。
- 仅配置真实可信的反向代理；错误的 `trusted-proxies` 会影响来源地址判断。
- TLS 私钥文件使用最小权限，禁止提交到 Git。
- 对日志、审计文件、线程快照设置访问控制与保留周期。

## 反向代理

只有连接来源命中 `server.lingtong.trusted-proxies` 时，才应信任代理转发头。不要为
图省事配置过宽网段。代理层还应限制请求大小、连接速率和管理路径访问。

## 管理 API

Bearer Token 本身不是完整身份治理方案。当前管理端适合受控环境中的节点诊断；它
尚不提供独立原生 TLS、多用户身份源和完整 RBAC。高要求环境应在前方配置 mTLS/VPN/
身份代理，并通过网络策略限制来源。

## 漏洞报告

不要在公开 Issue 中披露未修复漏洞、密钥、客户数据或未经脱敏的请求日志。请按照
仓库的 `SECURITY.md` 使用 GitHub Private Vulnerability Reporting；若该功能尚未启用，
先通过 `SECURITY.md` 中公布的私密渠道联系维护者。

## 许可证边界

公开源码使用 `AGPL-3.0-only`。不能履行 AGPL 义务的组织需要另行取得商业许可。
安全修复与商业授权是两个问题，发现漏洞不意味着获得额外授权。
